# 山海

本地交易研究工作台。在自己的电脑上看行情和图表，让 agent 直接读这张图，而不是在 TradingView 和交易所之间来回截图、每次再粘贴一次 API key。

## 它要接上的三件事

看图、看仓位、下单参考现在是断开的：在 TradingView 里分析，再换到币安这类交易所下单；agent 要看持仓时，密钥还得再交一次。

山海打算把这三件事留在同一台机器上：

1. **本地图表。** agent 直接读行情、K 线和已有标注，不用截图搬运。
2. **留在本机的交易所密钥。** 持仓和成本从本机读取，密钥不进入对话。
3. **图上的意图。** 人在图上标出自己的判断；agent 能读这些标记，也可以把分析写回图上。下单时，这张图就是对照。

下单仍然在交易所，由人完成。这个仓库没有下单接口。

把图表和另一套本地持仓记录对齐、让 agent 对照仓位和图表意图一起分析，是后续方向。这条连接还没有接到本仓库里。

## 现在已经能做的

- 本地图表：K 线、画线、指标、实验性 Pine v5/v6，以及独立的基础回测。
- 公开行情：币安现货推送，OKX / Kraken 的公开接口，以及 A 股、港股、美股等网页源。价格只来自这些源，失败时用已下载的缓存并标明时间。
- 本机上的 agent 可以通过 MCP 读取行情和共享图表，计算一组固定指标或现有回测。编辑凭据可以把批注写回共享图表。
- 服务开着时，未触发的价格提醒会在后台检查。通知渠道要自己配在本机，不随仓库提供。
- 仅在本机页面，可以用留在本机的模型密钥，让模型根据当前 K 线提出少量标注并画回图上。

国内期货账户桥默认关闭。它不是上面说的交易所持仓工作流。

这不是完整的 TradingView，也不是官方 Pine。指标预热、交易日历、合约和部分图形还不完整。

## 运行

需要 Node.js 22.19 或更高。

```sh
npm ci --ignore-scripts --no-fund --no-audit
npm start
```

打开 http://127.0.0.1:18765/ 。`npm start` 只监听本机，并先在本地生成 `dist/`。开发时用 `npm run dev`。

Windows 只给本机用时，双击 `start-local-windows.cmd`。要给同一私网里的其他设备用时，再用 `start-windows.cmd` 或 `npm run start:lan`。Mac 启动器按脚本所在目录定位项目。

Agent 接入、指标参数和局域网凭据见 [Agent 计算与共享图表](docs/agent-research.md)。公开行情的来源差异见 [行情与局域网](docs/lan-and-live.md)。

## 安全默认

- 普通启动只监听 `127.0.0.1`。局域网模式会监听所有网卡，但连接落在公网地址上会被拒绝。不要把端口转发到公网。
- 私网访问是明文 HTTP。页面上的连接凭据等同于密码，只在主机的 localhost 页面显示，保存在未跟踪的 `data/access.json`。
- 交易所密钥、模型密钥和通知 webhook 只放在本机 `data/` 或环境变量里。这些文件已忽略，不要提交。
- 终端不提供下单。
